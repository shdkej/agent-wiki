# 선택은 확인된 callback으로 확정한다

버튼이 전송되고 메시지가 보였다고 해서 선택이 끝난 것은 아니다. 실제 후속 작업은 복합 키와 callback을 확인해, 같은 선택이 맞는지 검증한 뒤에만 시작한다.

## 판단 순서

1. 전송 성공과 선택 확정을 분리한다.
2. `channel`, `thread`, `message`, `value`, `intent`가 모두 맞는지 본다.
3. 버튼 label이나 보이는 텍스트를 분기 키로 쓰지 않는다.
4. 같은 callback의 중복 수신은 한 번만 처리한다.
5. 선택 확정 전에 후속 작업을 시작하지 않는다.
6. callback이 오지 않으면 만료나 fallback 절차를 먼저 적용한다.

## 왜 필요한가

- 전송 완료는 도달 신호일 뿐, 사용자 결정의 증거가 아니다.
- 선택 확정이 느슨하면 잘못된 채널이나 다른 실행의 입력으로 후속 작업이 흘러간다.
- dedup과 first-wins가 없으면 재전송이나 재시작 뒤에 같은 작업을 여러 번 실행할 수 있다.
- 운영 절차를 선택 확정과 분리하면 질문, 승인, 실행, 기록을 더 안전하게 나눌 수 있다.
