# 리뷰 소스 라우팅과 현재성

OpenClaw 로컬 리뷰는 단일 원문을 요약하는 작업이 아니라, 여러 소스를 함께 읽고 현재성·출처·역할을 분리하는 운영이다.

## 핵심 원칙

- 데일리 리뷰는 Google Drive 일일 회고, 실제 대화 맥락, agent-wiki diary, 그리고 필요한 경우 Slack/Calendar 신호를 함께 본다.
- diary는 원문 대체물이 아니라 얇은 색인이다. 날짜별 원문은 `source/openclaw-system/data/daily-reviews/`에 남기고, 위키는 재사용 가능한 판단만 남긴다.
- 여행 맥락은 현재 도시와 다음 이동을 먼저 고정하고, 이미 지난 도시나 오래된 장면은 사용자가 다시 꺼낸 경우에만 재사용한다.
- 사용자의 발화와 SAM의 운영 처리는 분리한다. 사용자 의도, 자동화 처리, 후속 정리는 같은 문장에 섞지 않는다.
- Threads나 외부 공개 초안은 실제 사용자 발화와 현재 맥락이 있는 날에만 만든다. 맥락이 비면 억지로 채우지 않는다.

## 판단 순서

1. 오늘의 원문과 실제 대화 맥락을 먼저 확인한다.
2. diary와 log에 같은 날짜의 색인이 있는지 본다.
3. 현재성 게이트가 필요한 여행/콘텐츠/게시 판단인지 확인한다.
4. 사용자 발화 기반 소재가 없으면 공개 초안이나 추천을 생략한다.
5. 재사용 가능한 규칙만 concept, synthesis, maintenance, diary로 분리한다.

## 왜 필요한가

- 출처가 섞이면 사용자의 판단과 자동화 보조가 뒤섞여 재사용성이 떨어진다.
- 현재성이 흐려지면 오래된 도시, 오래된 장면, 오래된 제목이 다시 첫 액션으로 올라오는 드리프트가 생긴다.
- 리뷰는 운영 기록이 아니라 다음 판단을 위한 색인이어야 한다.
