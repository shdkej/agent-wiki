# 인간-에이전트 핏

장기 목표는 범용 지능을 더 높이는 것이 아니라, 사용자의 변하는 필요와 에이전트의 실행 방식, 판단 기본값, 노트에서 파생된 운영 기억 사이의 핏을 계속 맞추는 것이다.

## 핏을 개선하는 것

- 안정적인 선호를 더 잘 추출한다.
- 사용자가 직접 고친 버전과 에이전트가 유지한 버전을 비교한다.
- 드리프트와 불일치를 더 빨리 감지한다.
- 작업의 형태와 원하는 산출물을 더 잘 예측한다.
- 에이전트가 해도 되는 일, 사람이 다시 결정해야 하는 일, 하지 말아야 하는 일을 명시한다.

## 권한 경계

인간-에이전트 핏은 취향과 문체만의 문제가 아니다. 사용자가 무엇을 맡겨도 되는지 알 수 있을 때 첫 시도 부담이 줄고, 에이전트의 판단이 자기평가나 외부 실행으로 과장되어 읽히는 위험도 줄어든다.

특히 AI-native 제품은 `권고`, `판정`, `저장`, `공유`, `외부 실행`을 한 문장으로 섞지 않아야 한다. 각 단계마다 사용자가 위임한 것, 제품이 해도 되는 것, 사람 결정이 필요한 것, 보여줘야 할 증거를 분리하면 신뢰가 기능 설명이 아니라 활성화 장치가 된다.

여기에 credential 경계도 포함된다. 로그인, 비밀번호, 세션 같은 비밀값은 모델 프롬프트 안으로 넣지 않고 별도 실행 표면에 둬야 한다. 브라우저 원격 제어가 가능해져도 핵심은 `모델이 무엇을 아는가`보다 `비밀을 노출하지 않은 채 작업을 어디까지 이어갈 수 있는가`와 `어떤 라우터/재개 경로로 같은 일을 반복할 수 있는가`다.
